# Investigación SRS v1.0 - Equipo Los Marcianos

## 1. ¿Qué es un SRS?
Es el documento que describe QUÉ debe hacer el software, no CÓMO. Es el contrato entre cliente y desarrollador. Define requisitos funcionales y no funcionales.

## 2. Importancia del SRS
Sin SRS hay malentendidos, retrabajo y el cliente dice "no era lo que pedí". Ahorra tiempo, dinero y sirve como base para pruebas.

## 3. Estructura estándar (IEEE 830)
1. Introducción (Propósito, Alcance, Definiciones)
2. Descripción General (Perspectiva, Funciones, Usuarios)
3. Requisitos Específicos (RF y RNF, con ID único)
4. Anexos (Diagramas, Casos de uso)

## 4. Requisitos Funcionales vs No Funcionales
Funcional (RF): QUÉ hace. Ej: "El sistema debe permitir iniciar sesión"
No Funcional (RNF): CÓMO lo hace. Ej: "Tiempo de respuesta <2s, seguridad, usabilidad"

## 5. Características de un buen requisito
Debe ser: Claro, Medible, Alcanzable, Trazable (ID único RF-01), Verificable. Evitar ambigüedades como "rápido" o "fácil".
